# sgit axioms

## AX-CLI-CHECKOUT-REPO-TARGET: `sgit checkout <owner/repo|reponame>` Ensures A Valid Linked Main Worktree

`sgit checkout` MUST accept repository targets in addition to branch names:

- Outside a git repository, every target is a **repo target**.
- Inside a git repository:
  - local or `origin/<name>` branch → **branch target**
  - slash form under a branch namespace (`feature/`, `task/`, `project/`,
    `fix/`, …) → **branch target** (never misread as owner/repo)
  - GitHub-shaped `owner/repo` (or a path already present under bare/worktree
    roots) → **repo target**; if ensure fails, fall back to branch create
  - bare `reponame` with no matching branch → **repo target** via the same
    owner-resolution chain as `sgit clone` / `sgit open`, with branch-create
    fallback on failure

For a repo target, `sgit checkout` MUST:

1. Create all missing ancestors of the bare and main-worktree paths under the
   configured `bareRoot` / worktree root (never fail with a "can't write /
   No such file" error solely because those parents are missing).
2. Bare-clone when the bare is missing; materialize the main worktree when
   missing.
3. When the main worktree path exists but is **not** a valid linked worktree of
   the bare (missing or broken `.git`, or `git rev-parse` fails), re-materialize
   when safe (empty directory, or only a broken `.git` marker). Refuse with a
   clear error when non-git content would be destroyed.
4. After success, `git -C <path> rev-parse --is-inside-work-tree` is true and the
   common git dir is the bare. Print the absolute path on stdout only.

Complements [[ax-cli-checkout-sibling-worktree]] (branch path) without changing
the sibling-worktree / never-switch-in-place invariant.

### Why

Users navigate with `sgit checkout owner/repo` expecting ensure + `cd`. Treating
that form as a branch of the *current* repo creates wrong trees; missing parent
directories fail with write errors; existing non-git directories can be reported
ready without a git connection. A single verb that ensures a valid linked main
worktree keeps repo navigation aligned with the bare + worktree layout.

### How to apply

- Classify in `sgit-core` (`classify_checkout_target`); implement ensure in
  `ensure_repo_main_worktree` / `ensure_repo_main_worktree_from_url`.
- Reuse `bare_clone_from_url` + `create_worktree`; validate with
  `is_valid_linked_worktree` after every create.
- When `extensions.worktreeConfig` is enabled on the bare, write
  `core.bare=false` on the new worktree (same fix as submodule attach).
- CLI prints only the absolute path on stdout; diagnostics on stderr.
- Do not treat non-git directories as already-healthy worktrees in clone/open/checkout.

### Acceptance Checks

- `cargo test -p sgit-core checkout`
- `cargo test -p sgit checkout_parses_branch_arg`

## AX-SGIT-SHOVE-DETERMINISTIC-RECOVERY: `sgit shove` Always Terminates Pushed Or Cleanly Restored

`sgit shove` (and therefore `stokd shove`, which runs the same `sgit-core` flow)
MUST terminate in exactly one of two observable states:

- **(a) pushed** — the branch is on origin; or
- **(b) nothing pushed and restored** — the worktree is clean and NOT
  mid-operation, and the error names both safety backup branches.

It MUST NOT leave a rebase, merge, or cherry-pick in progress on any failure
path. Specifically:

1. **Stale-lock reaping is mechanical, never modelled.** Before mutating
   anything, shove MUST reap stale git lock files (`index.lock`, `HEAD.lock`,
   `shallow.lock` under the worktree's git dir) **only** when no live process
   holds them, and MUST fail fast naming the holding PID when one does.
2. **Shove serializes against itself.** Shove MUST hold a repo-scoped sgit lock
   so two concurrent shoves in one worktree cannot race each other's index.
3. **Pre-existing in-progress state is explicit.** Shove MUST detect
   `rebase-merge/`, `rebase-apply/`, `MERGE_HEAD`, or `CHERRY_PICK_HEAD` on
   entry and either adopt or abort it explicitly — never proceed over it.
4. **Sync failure is classified, not boolean.** A failed `git pull --rebase`
   MUST be classified as `Completed | Conflicts | Blocked | Fatal`. Only
   `Conflicts` may dispatch a `ConflictResolver`; `Blocked` gets bounded
   remediation plus retry; `Fatal` aborts and restores. An empty unmerged-path
   set MUST NEVER be reported as a successful resolution.
5. **Conflict resolution loops.** Resolution MUST loop until no rebase is in
   progress, because a rebase stops once per conflicting commit.
6. **Binary conflicts are their own class.** Conflicts on binary paths MUST be
   surfaced to the resolver as a distinct class carrying an ours/theirs/newest
   decision, and MUST NEVER be marker-scanned.

Complements the `ConflictResolver` seam without changing it: mechanical recovery
belongs below the seam so `sgit` (editor resolver) and `stokd` (agent resolver)
inherit it identically.

### Why

`push_with_sync` treats any `pull --rebase` failure as a conflict
(`crates/sgit-core/src/shove.rs:192`) and any empty unmerged set as a successful
resolution (`crates/sgit-core/src/shove.rs:252-256`). A stale `index.lock` left
by a killed sibling process therefore produced a silent no-op "resolution", a
guaranteed non-fast-forward push rejection, and a worktree stranded mid-rebase
whose retry then fails differently — the observed `stokd-cloud/mono` failure.
Recoverability must be mechanical and deterministic; model escalation is for
semantic conflicts only, never for environment faults.

### How to apply

- Keep every recovery step in `sgit-core` **below** the `ConflictResolver` seam.
- Add lock reaping and in-progress-state detection as pure, unit-testable
  classifiers in `shove.rs` (path/mtime/holder inputs in, decision out).
- Serialize with `sgit-core/src/lock.rs` rather than a second locking scheme.
- Replace the boolean branch in `push_with_sync` with a `SyncOutcome` enum;
  never collapse `Blocked` into `Conflicts`.
- Escalate to a resolver only for text and structural conflicts already
  classified by `UnmergedKind`; binary paths carry an explicit side choice.

### Acceptance Checks

- `cargo test -p sgit-core shove`
- `cargo test -p sgit-core lock`
- `cargo test -p sgit shove`
